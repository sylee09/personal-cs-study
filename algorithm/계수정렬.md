### 계수 정렬이란?
- 계수 정렬 (카운팅 소트)는 구별되는 키 값들을 소유하는 객체의 수를 계수하고 출력 시퀀스에 각 키 값의 위치를 결정하기 위한
  해당 계수에 전위합을 적용함으로써 동작함
- 계수 정렬은 비교 정렬이 아님 => O(nlgn)보다 빠를 수 있다.
  - N개 원소의 배열이 있을 때, 이를 모두 정렬하는 가짓수는 N!.
  따라서, Comparison Sort를 통해 생기는 트리의 말단 노드가 N! 이상의 노드 갯수를 갖기 위해서는, 2^h >= N! 를 만족하는 h를 가져야 하고, 이 식을 h > O(nlgn)을 가져야 한다. 
  (h는 트리의 높이 즉 Comparison sort의 시간 복잡도임)

### 알고리즘
1. 초깃값(array) : [7,2,3,5,7,1,4,6,7,5,0,1]
- array[0] = 7 -> counting[7]++
- array[1] = 2 -> counting[2]++
- array[2] = 3 -> counting[3]++
- ...
- array[11] = 1 -> counting[1]++
- => counting : [0:1,1:2,2:1,3:1,4:1,5:2,6:1,7:3]
2. counting 배열의 각 값을 누적합으로 변환
- counting : [0:1,1:3,2:4,3:5,4:6,5:8,6:9,7:12]
- counting 배열의 각 값은 (시작점 - 1)을 알려줌
3. [7,2,3,5,7,1,4,6,7,5,0,1] 뒤 부터 순회
- 1 => counting[1]-- 그후 counting[1]의 값이 1의 위치
- 0 => counting[0]-- 그후 counting[0]의 값이 0의 위치
- 5 => counting[5]-- 그후 counting[5]의 값이 5의 위치
- ...
- 7 => counting[7]-- 그후 counting[7]의 값이 7의 위치
- => result[0,1,1,2,3,4,5,5,6,7,7,7]

### 알고리즘
```java
int arr[5]; // [5,4,3,2,1]
int sorted_arr[5];
// 과정 1 - counting 배열의 사이즈를 최대값 5가 담기도록 크게 잡기
int counting[6];	// 단점 : counting 배열의 사이즈의 범위를 가능한 값의 범위만큼 크게 잡아야 하므로, 비효율적이 됨.

// 과정 2 - counting 배열의 값을 증가해주기.
for (int i = 0; i < arr.length; i++) {
    counting[arr[i]]++;
}
// 과정 3 - counting 배열을 누적합으로 만들어주기.
for (int i = 1; i < counting.length; i++) {
    counting[i] += counting[i - 1];
}
// 과정 4 - 뒤에서부터 배열을 돌면서, 해당하는 값의 인덱스에 값을 넣어주기.
for (int i = arr.length - 1; i >= 0; i--) {
    counting[arr[i]]--;
    sorted_arr[counting[arr[i]]] = arr[i];
}
```
### 시간복잡도
- O(N+K)
- N: 원소 배열을 순회하는 시간
- K: 계수 배열을 생성하고 누적합을 계산하는 시간

### 공간복잡도
- O(N+K)
- k: 계수 배열(counting 배열)의 크기
- N: 정렬된 결과를 저장할 출력 배열(sorted_arr)의 크기

### 장점
- O(N+K))으로 속도가 빠르다
- 안정정렬이다.

### 단점
- 추가적인 메모리 필요 (필요한 메모리가 매우 큼)
