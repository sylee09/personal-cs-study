### 삽입 정렬이란?
- 삽입 정렬은 손 안의 카드를 정렬하는 방법과 유사하다.
- 삽입 정렬은 자료 배열의 모든 요소를 앞에서부터 차례대로 이미 정렬된 배열 부분과 비교하여,
자신의 위치를 찾아 삽입함으로서 정렬을 완성하는 알고리즘.

### 알고리즘
- 우선 첫번째 인덱스인 0의 원소는 이미 정렬된 상태 (왼쪽은 이미 정렬된 상태)
- 인덱스가 1 ~ n-1 원소를 차례대로 왼쪽에 정렬된 원소집합(왼쪽)에 넣는 것
- 이미 카드가 정렬된 경우 O(n)의 시간복잡도를 가진다.

### 예시
- 초깃값 : [7,2,0,1,5,6,4] 일때 [7 |2,0,1,5,6,4]로 나눌수있음 (| 기준으로 왼쪽은 정렬된 상태 오른쪽은 정렬되지 않은 상태)
- 2는 7보다 작으므로 [2,7| 0,1,5,6,4] 로 정렬됨
- 0은 2,7 보다 작으므로 [0,2,7 | 1,5,6,4] 로 정렬됨
- 1은 0보다 크고 2,7보다 작으므로 [0,1,2,7| 5,6,4]로 정렬됨
- 5는 2보다 크고 7보다 작으므로 [0,1,2,5,7| 6,4]로 정렬됨
- 6은 5보다 크고 7보다 작으므로 [0,1,2,5,6,7| 4]로 정렬됨
- 4는 2보다 크고 5보다 작으므로 [0,1,2,4,5,6,7]로 정렬되고 정렬 완료

### 알고리즘
```java
void insertionSort(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        int temp = arr[i];
        int aux = i - 1;

        while ((aux >= 0) && (arr[aux] > temp)) {
            arr[aux + 1] = arr[aux];
            aux--;
        }
        arr[aux + 1] = temp;
    }
}
```
### 시간복잡도
- 바깥 for문은 n-1번 반복하고 안쪽 for문은 최악의 경우 왼쪽의 원소 개수 만큼 비교한다.
  - 이 경우 1+2+3+...+n-1 => (n-1)*n/2 => O(n^2)
- 최선의 경우는 안쪽 for문이 최대 1번 비교한다. => O(n-1) => O(n)

### 공간복잡도
- N의 크기의 배열만을 사용하고 추가적인 메모리가 필요하지 않으므로 O(1)이다.

### 장점
- 최선의 경우 O(n)으로 속도가 빠르다.
- 다른 메모리 공간을 필요로 하지 않는다.
- 안정 정렬이다.

### 단점
- 최악의 경우 버블정렬, 선택정렬과 같이 O(n^2)의 시간 복잡도를 가진다.
