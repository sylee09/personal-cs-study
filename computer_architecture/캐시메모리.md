### 캐시 메모리
- 속도가 빠른 장치와 느린 장치에서 속도 차이에 따른 병목 현상을 줄이기 위한 메모리
- CPU 코어와 메모리 사이의 병목 현상 완화
- 웹 브라우저 캐시 파일은, 하드디스크와 웹페이지 사이의 병목 현상을 완화
```
CPU 코어와 메모리 사이의 병목 현상 완화
웹 브라우저 캐시 파일은 하드디스크와 웹페이지 사이의 병목 현상을 완화
```
CPU가 주기억장치에서 저장된 데이터를 읽어올 때, 자주 사용하는 데이터를 캐시 메모리에 저장한 뒤, 다음에 이용할 때 주기억장치가 아닌 캐시 메모리에서 먼저 가져오면서 속도를 향상시킨다.
(속도는 장점이지만 용량이 적고 비용이 비쌈)
- CPU에는 캐시 메모리가 2~3개 정도 사용됨 (L1, L2, L3 캐시 메모리라고 불림)
- L1 캐시부터 먼저 사용되고 여기서 데이터를 찾지 못하면 L2로 감
- 속도와 크기에 따라 분류됨
- L1 : CPU 내부에 존재
  - 만약 L1 캐시가 128kb면, 64/64로 나누어 64kb에 명령어를 처리하기 직전의 명령어를 임시 저장하고, 나머지는 실행 후 명령어를 임시저장함.
- L2 : CPU와 RAM 사이에 존재
- L3 : 보통 메인보드에 존재함.

### 캐시 메모리 작동 원리
- 시간 지역성
  - for나 while 같은 반복문에 사용하는 조건 변수처럼 한번 참조된 데이터는 잠시후 또 참조될 가능성이 높음
- 공간 지역성
  - A[0], A[1]과 같은 연속 접근 시, 참조된 데이터 근처에 있는 데이터가 잠시후 또 사용될 가능성이 높음

캐시에 데이터를 저장할 때는 공간 지역성을 최대한 활용하기 위해 해당 데이터뿐만 아니라, 옆 주소의 데이터도 같이 가져와 미래에 쓰일 것을 대비

### 캐시 미스 경우 3가지
1. Cold miss 
- 해당 메모리 주소를 처음 불러서 나는 미스
2. Conflict miss
- 캐시 메모리에 A와 B 데이터를 저장해야 하는데, A와 B가 같은 캐시 메모리 주소에 할당되어 있어서 나는 미스 (direct mapped cache에서 많이 발생)
- direct mapped cache: 메인 메모리(주기억장치)의 각 데이터 블록을 캐시 메모리의 오직 하나의 고정된 위치에만 저장하도록 1:1 매핑하는 방식
3. Capacity miss
- 캐시 메모리의 공간이 부족해서 나는 미스

### 캐시 구조 및 작동 방식
1. Direct Mapped Cache
---
가장 기본적인 구조로, 메인 메모리의 여러 주소가 캐시 메모리의 한 주소에 대응되는 방식

간단하고 빠른 장점이 있지만, Conflict Miss가 발생하는 것이 단점

2. Fully Associative Cache
---
비어있는 캐시 메모리가 있으면, 마음대로 주소를 저장하는 방식

저장은 간편하지만 찾을때는 조건이나 규칙이 없어서 트정 캐시 set 안에 있는 모든 블럭을 한번에 찾아 원하는 데이터가 있는지 검색해야 한다.

3. Set Associative Cache
---
- Direct + Fully 방식. 
- Cache를 n개의 block으로 구성된 set으로 나눔. 
- 메모리에 있는 block은 cache의 특정한 set에 매핑되고, 해당 block은 set 안의 아무 위치에 들어갈 수 있다.
- Direct에 비해 검색 속도는 느리지만, 저장이 빠르고 Fully에 비해 저장이 느린 대신 검색이 빠른 중간형.
